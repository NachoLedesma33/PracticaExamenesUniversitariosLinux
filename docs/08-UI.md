# 08 — Interfaz de Usuario

> Componentes, layout de 3 paneles, flujo de interacción y sistema de temas (claro/oscuro).
> Verificado el 2026-08-06 contra `src/App.tsx`, `src/components/*` y `src/index.css`.

## 1. Estructura general

```
App
└── Layout
    ├── header            (logo, toggle sidebar, toggle panel derecho, toggle tema)
    ├── aside (izq, w-80) ← LeftPanel
    │   ├── ImportZone
    │   ├── ExerciseGeneratorPanel
    │   ├── ModoLibrePanel
    │   ├── buscador
    │   ├── banner "Todas las categorías" / path activo
    │   ├── acordeón de grupos (PARCIAL 1/2/3, FINALES, Original)
    │   └── lista de ChallengeCard
    ├── main (flex-1)     ← Terminal
    │   ├── barra de título (3 puntos, "terminal — bash", botón minimizar)
    │   ├── ChallengeBanner (enunciado + pista + respuesta texto/script)
    │   ├── TerminalOutput (historial renderizado)
    │   └── TerminalInput  (prompt, tab completion, historial, capture mode)
    └── aside (der, w-80) ← RightPanel
        ├── VFSExplorer   (árbol del sistema de archivos)
        └── InodeInspector (detalle del nodo seleccionado)
```

## 2. Layout y paneles

### `Layout.tsx`

- Contenedor `h-screen flex flex-col`. Header con:
  - Logo "SO-practica" + subtítulo.
  - 3 botones ghost: toggle `sidebarOpen`, toggle `challengePanelOpen`, toggle `theme`.
- Filas centrales: sidebar izquierdo (w-80), terminal (flex-1), sidebar derecho (w-80). Paneles ocultables independientes.
- Tema: `App.tsx` pone la clase `dark` en el div raíz según `store.theme`.

### `LeftPanel.tsx`

- **Agrupación por categorías**: cada categoría de `Challenge` se agrupa según su prefijo:
  `PARCIAL 1 - ` → grupo "PARCIAL 1", `PARCIAL 2 - ` → "PARCIAL 2", `PARCIAL 3 - ` → "PARCIAL 3", `FINALES - ` → "FINALES", cualquier otra → "Original".
- **Buscador**: filtra por `instruction`, `solutionHint` o `commands`.
- **Filtros**: "Todas las categorías" o una categoría puntual; ordena generados primero (`generated` → -1).
- **Progreso**: cada grupo/categoría muestra `completados/totales` y una barra (gradiente cyan→verde).
- Acordeón: grupos expandibles (por defecto abiertos `PARCIAL 1` y `FINALES`).
- Integra `ImportZone`, `ExerciseGeneratorPanel` y `ModoLibrePanel` (detalle en `07-GENERADOR-EJERCICIOS.md`).
- Banner de **path activo** (modo libre): muestra progreso y "Click para salir". El próximo ejercicio pendiente del path se resalta con badge "Siguiente" (amarillo).

### `RightPanel.tsx`

- `VFSExplorer` + divisor + `InodeInspector`.

### `VFSExplorer.tsx`

- Árbol recursivo `TreeNode` sobre `store.vfs['/']`.
- Click en directorio: expande/colapsa **y** setea `cwd` (doble función). Click en archivo: selecciona para inspección.
- Directorios primero, orden alfabético; resalta el `cwd` actual (cyan) y el nodo seleccionado.

### `InodeInspector.tsx`

- Detalle del nodo seleccionado (`store.selectedNodePath`): nombre, tipo, ruta, inodo, dueño, grupo, tamaño (B/KB/MB).
- Render de permisos: los caracteres `rwx` coloreados (verde lectura/escritura, cyan ejecutable, amarillo setuid/setgid/sticky).
- Vista previa de contenido (primeros 500 bytes) para archivos.

## 3. Terminal

### `Terminal.tsx`

- Ventana estilo macOS: 3 puntos de color (rojo/amarillo/verde), título "terminal — bash", botón minimizar.
- Si el ejercicio activo es de tipo `text` **scripting** (categoría contiene "scripting" o "finales"), oculta el output/input clásicos y deja el `ChallengeBanner` ocupando todo (textarea grande para scripts).
- Efecto `glow-edge` + `animate-pulse-glow` (borde con gradiente cyan/verde animado).

### `ChallengeBanner.tsx`

- Muestra categoría, dificultad, estado "Completado".
- Enunciado colapsable (ChevronUp/Down).
- **Pista progresiva**: `getHint(challenge, attempts)` — la pista cambia según cantidad de intentos (máquina de estados del hint-system, ver `03-VALIDACION.md`). El contador muestra `(intentos+1/total)`.
- Botón "Ver pista" expande pista + solución.
- **Respuesta de texto**: para ejercicios `text` muestra un textarea. Enter envía (o Shift+Enter nueva línea); en modo scripting, Tab inserta 2 espacios. Feedback de resultado (verde/rojo) con botón "Reintentar".

### `TerminalOutput.tsx`

- Renderiza `store.history` con `$ comando`, salida y `simulatedOutput` (amarillo).
- Errores (`exitCode !== 0`) en rojo; auto-scroll al fondo en cada entrada nueva.
- Bienvenida inicial si no hay historial.

### `TerminalInput.tsx`

- Prompt `user@hostname:cwd$` (colores del tema).
- **Tab completion**: autocompleta rutas VFS contra lo tipeado; si hay múltiples coincidencias muestra chips de sugerencias (máx. 12).
- **Historial**: ArrowUp/ArrowDown (del session slice).
- **Comandos especiales**: `help` (lista de comandos), `reset` (limpia historial), `resetfs` (restaura VFS).
- **Capture mode**: `cat > archivo` activa el modo captura (`captura&gt;` prompt); Ctrl+D guarda el archivo con `createFile` y revalida el ejercicio.
- **Validación**: tras ejecutar un comando, llama `validateCommand(cmd, exitCode)` y registra intento. Si pasa → "✅ ¡Correcto!". Para ejercicios `text` valida directamente la respuesta tipeada.
- `pendingInput`: permite inyectar un comando desde otro panel (botón "Pegar en la terminal" del ChallengeCard).

## 4. Cards y ejercicios

### `ChallengeCard.tsx`

- Estado visual según: activo/success/error/completado (opacidad)/siguiente en path (amarillo)/generado (púrpura + badge "Generado").
- Click → `setCurrentChallenge(id)` (aplica `initialState` del ejercicio al VFS).
- Al estar activo, muestra expandido: botón solución, pista, bloques opcionales `executionCommand` (con copiar al portapapeles y "pegar en terminal"), `expectedOutput`, último error y badges de comandos.
- Badge de dificultad: fácil=success, medio=warning, difícil=danger.

### `ImportZone.tsx`

- Drag & drop o click para importar `.md`/`.json` → `parseMarkdownToChallenges` / `parseJsonToChallenges` (`src/utils/mdParser.ts`).
- Valida extensión, muestra cantidad detectada vs. total actual, importa con `importChallenges` (dedupe por id).

## 5. Sistema de temas

Definido en `src/index.css` (Tailwind v4):

- **`@theme`**: paleta `surface-*` (slate 50→950), colores terminal (bg, fg, green, cyan, yellow, red, dim), glass y glow shadows.
- **`:root`** (claro): ~35 custom properties de UI (`--sidebar-fg`, `--card-bg`, `--input-bg`, `--banner-*`, `--textarea-*`, `--badge-*`, `--term-header-bg`, `--term-border`) + override de los colores terminal a variantes claras.
- **`.dark`**: redefine las mismas variables para tema oscuro (fondo `#0d1117` de GitHub, texto `#e6edf3`).
- **Clases utilitarias**: `.sidebar-fg`, `.card-bg`, `.hover-bg`, `.track-bg`, `.banner-bg`, `.textarea-bg`, etc. mapean 1:1 con las variables → los componentes usan variables (cambio de tema sin re-render de estilos).
- **Efectos**: `.glass`/`.glass-strong` (backdrop blur + saturación), `.glow-edge` (borde gradiente), animaciones `fadeSlideIn`, `treeEnter`, `barFill`, `pulseGlow`, `successPulse`.
- **Tipografía**: JetBrains Mono / Fira Code / Cascadia Code / Consolas (monospace para todo el simulador).
- Scrollbars finas; el switch de tema está en `store.theme` (`toggleTheme`).

## 6. Flujo de interacción típico

1. Usuario elige ejercicio en `LeftPanel` → `setCurrentChallenge` (aplica `initialState`).
2. `ChallengeBanner` muestra enunciado + pista.
3. Usuario tipea en `TerminalInput` → `executeCommand(cmd)` → `addToHistory` (render en `TerminalOutput`).
4. El motor llama `validateCommand` → `recordAttempt` + `setLastValidation`.
5. `ChallengeCard` y `ChallengeBanner` reflejan éxito/error; si pasa, `markChallengeCompleted`.
6. `RightPanel` muestra el VFS mutado (el terminal modifica el mismo store) e inspector de nodos.

Todo el estado compartido vive en Zustand (ver `09-ESTADO.md`); los componentes son puramente derivados del store salvo el estado local de UI (paneles abiertos, búsqueda, textarea).
